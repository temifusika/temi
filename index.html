    How I build with AI

    I treat AI agents like a capable delivery team: clear briefs, hard acceptance criteria, and nothing ships without a test and my sign-off.

    1. I write the briefScope, acceptance criteria and the rules the system must never break.
    2. An agent buildsOne focused session per change, working from the handover pack.
    3. Tests decideUnit, database, isolation and session tests gate every merge.
    4. I approve and shipReview, deploy, verify live. Rollback is one command.
    5. Handover noteEach session ends with a handover so the next starts with full context.
    AI proposes, people decideseer.’s AI can read a bill and suggest fields, but it cannot write to the database. A person confirms and a second person verifies.
    Built, tested, then switched onBill reading is built and tested against a stub, with spend caps and a feature flag. It stays off until the privacy review is signed off and real costs are measured.
    Knowledge that compoundsA prompt playbook of 20+ tested recipes and a handover note after every session, so lessons are written down once and reused.
    Live data changes, safelyA read-only check first, a backup and a rollback file for every change, and the database updated before the code that uses it.
